# PRD · 会议登记 × 任务闭环 × 主题化甘特

## 1. 背景与目标

### 1.1 现象：每一段都能用，连起来就顺不起来

用户（业务主管视角）的原话是「整个操作体验不是很顺畅」，它由三处具体的断点组成，均已核对代码：

| 断点 | 现状（代码证据） | 用户感受 |
| --- | --- | --- |
| 会议登记要填两遍人 | `web/src/pages/MeetingsPage.vue:360` 主持人是自由文本 `AppInput`；同页 `:371` 参会人是把全部启用用户铺成复选框（`:370` 的 `activeOwners` 全量渲染，无搜索） | 主持人写了名字却和系统用户关联不上；人一多，参会人要在一屏几十个复选框里找 |
| 建完会才能录决议 | 建会接口只收会议字段，决议项必须进详情页逐条新增（每条一次 POST） | 一次例会 5 条决议 = 建会 1 次 + 录 5 次 + 转任务 1 次，4 次跨页 |
| 会议里看不到任务全局 | `MeetingDetailPage.vue:511` 只有每行一个任务状态链接，没有聚合视图 | 想知道「这个会派出去的 5 条活干到哪了」，只能一条条点进去 |
| 任务回不到会议 | `TaskDetailPage.vue:357` 来源会议链接对所有角色渲染，但 `/meetings/:id` 路由 `roles: ['ADMIN']` | OWNER/EXEC 点一下就被守卫弹到 403，比不提供入口更差 |
| 没有时间维度 | `tasks` 只有 `due_date`（`V1__schema.sql:67`），无计划开始日期 | 只能看「什么时候截止」，看不出「这季度铺了什么、哪里挤在一起、哪里已经压线」 |
| 没有主题维度 | 任务只有来源（会议/项目/说明）与项目，没有「主题」主数据 | 主管无法按「Q4 交付冲刺」这类主线看全局，只能按项目碎片化地看 |

### 1.2 目标

1. **会议登记一次填完**：人和决议项都在建会表单里一次录完，会议详情一屏看清「人 → 决议 → 任务 → 状态」。
2. **闭环贯穿且只有一套口径**：派发 → 进行 → 提交 → 验收 → 完成 的步进在任务详情可见；任务池、看板、矩阵、会议、甘特共用同一状态词与同一逾期判定（不新增状态、不改验收权限）。
3. **主题化甘特给主管看全局**：新增「主题」主数据，任务可挂主题；甘特按「主题主行 + 项目子行」出条，支持日/周/月缩放，逾期与风险一眼可定位。

### 1.3 成功度量（可核对）

- 新建一场带 5 条决议的会议：跨页次数从 4 次降为 1 次（表单提交后直接落在会议详情）。
- 主管打开甘特：首屏能看到「逾期 N / 风险 N / 进行中 N / 待验收 N / 已完成 N」，且点击数字即可筛出对应条。
- 同一任务在任务池、看板、矩阵、会议进度区、甘特五处的状态词与逾期天数完全一致（AC-7 逐条断言）。
- 既有基线不回退：server 248 例、web 188 例中无一条失败。

## 2. 用户故事与验收标准

### US-1 作为 ADMIN，我建会时就能把人、决议、主题一次录完（AC-1 ~ AC-5）

**AC-1 人员关联：主持人、参会人都从用户里选（P0）**
- 主持人改为可搜索的单选人员选择器：只列启用用户，输入姓名即时过滤；选中后该人自动加入参会人（可手动移除）。
- 参会人改为可搜索多选 chip：输入过滤、重复选择取唯一、支持整体清空；不再把全部用户铺成复选框。
- 提交契约不破：`host` 仍是姓名文本（`meetings.host VARCHAR(64)` 不动），`attendeeIds` 为唯一 id 数组；**数据库零迁移**。
- 历史会议（`host` 为自由文本）打开编辑：原文原样保留并标注「非系统用户」；不改人直接保存，`host` 逐字不变；改成系统用户则按新值保存。
- 验证：web 新增用例覆盖「选中主持人 → 自动进参会人」「输入过滤」「历史自由文本保留」；server 覆盖 `host` 修剪、`attendeeIds` 去重。

**AC-2 建会时一并登记决议项（P0）**
- 新建会议表单新增「决议事项（可选）」区：可添加 0..N 行，每行含 描述 / 负责人 / 截止日期（字段规则同 r1 AC-3：描述 ≤100 字、负责人 1 人、截止日期必填）。
- 一次提交、同一事务：会议与全部行要么全落库、要么全不落；任一行不合法时会议**不创建**，错误定位到「第 K 行 · 字段」并聚焦该输入（沿用 r6 的 `fieldErrors` 回填口径，形如 `items[1].dueDate`）。
- 成功后直接进入会议详情，N 条决议项按录入顺序展示，「已转 0 / 共 N」计数正确。
- 0 行时行为与现状完全一致（只建会议）。
- 验证：server 断言「第 2 行截止日期非法 → `meetings` 行数不变」；web 断言错误落在第 2 行且页面不跳转。

**AC-3 决议项连续录入（P1）**
- 会议详情「新增决议事项」：Enter 提交当前行并把焦点移到新行「描述」，Esc 取消；连续录 3 条无需移动鼠标。
- 提交失败时焦点回到出错单元格，已填写内容不被清空。
- 批量勾选转任务的既有行为不变：幂等、部分成功时同时报 created 与 skipped。

**AC-4 会议详情「任务进度」聚合区（P0）**
- 会议详情新增任务进度区，聚合该会议已转出的任务：标题 / 负责人 / 状态徽标 / 截止日期 / 逾期天数 / 风险标记；行点击进入任务详情。
- 口径唯一：决议项总数 M、已转 N、未完成 U、逾期 O、已完成 D 由同一份数据算出；`已转 N/M` 与列表行数一致，不得出现两套计数。
- 全部任务完成显示「已闭环」（沿用 r1 AC-5），有未完成显示「未完成 U 条」，一条未转显示「待派发」。
- 空态文案：`暂无已转任务，勾选上方决议项一键派发`；加载失败给重试，不整页白屏。
- 验证：造 3 条决议（1 已转已完成、1 已转逾期、1 未转）→ 断言 M=3、N=2、逾期=1、未完成=1、状态「未完成 1 条」。

**AC-5 任务 ↔ 会议不再撞 403（P1）**
- 任务详情来源区：来源为会议时，会议标题对 ADMIN 渲染为链接（进入会议详情并高亮/滚动到该任务对应的决议项行）；EXEC/OWNER 渲染为纯文本并提示「仅管理员可查看会议」，不产生可点击死路。
- 会议详情任务进度区的行链接（会议 → 任务）保持可用；从任务详情返回会议时保留会议详情的列表状态（不因返回而丢失折叠/勾选）。
- 验证：OWNER 打开会议来源任务，来源区无可点击跳转、无 403；ADMIN 点击后会议详情定位到对应决议项。

### US-2 作为任一角色，我看到的闭环与口径是同一套（AC-6 ~ AC-7）

**AC-6 任务详情五步闭环条（P0）**
- 顶部「派发 → 进行 → 提交 → 验收 → 完成」步骤条：`PENDING` 高亮第 1 步、`IN_PROGRESS` 第 2 步、`PENDING_ACCEPT` 第 4 步（提交已完成、验收进行中）、`DONE` 第 5 步；`CANCELLED` 显示分叉「已取消」并灰化后续步骤。
- 每步旁「下一步」提示写明可执行人：负责人「开始处理」/「提交交付」，派发人「验收通过 / 打回」，DONE 无操作。
- **不新增状态、不新增接口、不改权限**：动作按钮复用现有 `TaskActions`，权限仍只由服务端 `TaskAccessGuard` 决定，前端只做展示。
- 验证：三角色在 `IN_PROGRESS` / `PENDING_ACCEPT` 下看到的「下一步」与可点按钮符合现有权限矩阵；OWNER 在 `PENDING_ACCEPT` 不出现验收按钮。

**AC-7 状态 / 逾期 / 风险同源（P0）**
- 任务池、看板、矩阵、会议任务进度区、甘特五处：状态词同一套（待开始/进行中/待验收/已完成/已取消）；逾期判定同一函数（`due_date < 今天` 且未完成）；逾期天数一致。
- 边界必须一致：`due_date = 今天` → 未逾期；`due_date = 昨天` → 逾期 1 天；`DONE`/`CANCELLED` → 永不计逾期。
- 风险口径唯一：**逾期未完成** 或 **待验收且 `submitted_at` ≤ 今天−3 天**（提交后压了 3 天无人验收，本身是督办问题）；甘特与看板的「风险」数字必须相等。
- 甘特接口直接返回 `isOverdue / overdueDays / isAtRisk`，前端不得自算日期差（grep 断言：甘特组件内不存在基于 `dueDate` 的日期比较）。
- 验证：同一 task id 在五处断言一致；server 新增 3 条边界用例（今天 / 昨天 / 已完成）。

### US-3 作为 EXEC，我按主题看全局，逾期和风险一眼定位（AC-8 ~ AC-13）

**AC-8 主题主数据（P0）**
- `系统设置 → 主题配置`（与项目配置同构）：列表含 名称 / 颜色 / 排序 / 启用 / 引用任务数；支持新增、编辑、停用、删除。
- 规则：名称 2–20 字且全表唯一（含停用）；颜色从 8 色预设中选，默认按序分配；最多 100 个；被任务引用只能停用不可物理删除（409 + 可读文案）；停用后不可被新选，历史任务显示「（已停用）」。
- 接口：`GET /api/themes` 全员可读（任务表单与标签需要），写接口仅 ADMIN（非 ADMIN 403）。
- 验证：server 覆盖 名称唯一 / 上限 / 被引用删除 409 / 停用后不可选；web 覆盖表单校验与列表操作。

**AC-9 任务挂主题（P0）**
- 三个入口都能挂：新建任务抽屉、任务编辑、决议项转任务；均允许留空（= 未归主题）。
- 任务表单新增可选「计划开始日期」：留空时甘特按创建日推算；填了必须 ≤ 截止日期，否则 422 回填到字段。
- 服务端校验：`themeId` 不存在或已停用 → 422 `fieldErrors.themeId`，前端回填并聚焦；`plannedStartDate > dueDate` → 422 `fieldErrors.plannedStartDate`。
- 展示：任务详情、任务池、会议任务进度区、甘特显示主题标签；唯一渲染组件 `ThemeTag.vue`（未挂主题不渲染占位、停用加后缀、颜色来自接口），页面不得自拼颜色或自行比较 `enabled`。
- 编辑任务仍不改来源字段（r1 AC-4 不变）。
- 验证：spec 覆盖「选停用主题 → 422 回填」「转任务带主题落库」「ThemeTag 三种态（正常/停用/未挂）」。

**AC-10 甘特视图（P0）**
- 路由 `/gantt`（侧栏「工作台 · 进度甘特」），仅 ADMIN/EXEC 可见可访问；OWNER 侧栏不出现、直访 403。
- 分组两级：主题主行（按 `sort_no`）→ 项目子行（按项目 `sort_no`）→ 任务条；未挂主题的任务归「未归主题」主行（**置底**），未指定项目的归「未指定项目」子行；主题行、项目行都可折叠/展开。
- 时间轴三档：日（14 天/屏）、周（12 周/屏，默认）、月（6 个月/屏）；`← 上一屏 / 下一屏 → / 回到今天`；「回到今天」恢复默认窗口（周档：今天所在周往前 2 周）。
- 任务条：起点 = 计划开始日期，为空时用创建日期并在条上标注「按创建日推算」；终点 = 截止日期；最短渲染 1 天宽。
- 着色沿用现有语义色：待开始灰、进行中蓝、待验收橙、已完成绿、已取消灰虚线，逾期加红色描边；悬停 tooltip 显示 标题 / 负责人 / 来源 / 起止 / 状态 / 逾期天数；点击进入任务详情。
- 图例常驻（5 状态 + 逾期）；空窗口不渲染空白画布，给「扩大范围（本季）/ 回到今天」。
- 验证：web 覆盖三档刻度生成、折叠、未归主题置底分组；server 覆盖窗口查询与分组排序。

**AC-11 风险一眼定位（P0）**
- 顶部摘要条：逾期 N / 风险 N / 进行中 N / 待验收 N / 已完成 N，与看板同源同义；点击任一数字即应用对应筛选。
- 「仅看逾期与风险」开关（默认关）：开启后只保留风险条并自动展开其所属主题/项目行；无风险时空态提示「当前窗口内无风险任务」。
- **逾期条不被时间窗裁掉**：即使 `due_date` 早于窗口左边界，仍渲染在窗口最左侧并标注「逾期 N 天（超出窗口）」。
- 折叠状态在当前会话内保持（切档、翻屏、筛选不重置）；首屏默认全展开，主题数 >12 时默认折叠「既无风险又无逾期」的主题。
- 验证：把窗口右移一屏，逾期条仍在（断言其 x 坐标 == 窗口左边界）。

**AC-12 甘特边界与性能（P1）**
- 单次返回上限 300 条，超出返回 `truncated=true` 并给窗口内总数，顶部提示「窗口内共 N 条，当前显示 300 条，请缩小时间范围或按负责人筛选」。
- 切档、翻屏、筛选各只发 1 次请求（无重复/并发请求）；加载中显示骨架，不出现整页白屏或旧数据闪烁。
- 300 条任务 + 20 个主题时，切档与翻屏在 1.5s 内完成渲染（人工计时并留证据）。
- 验证：web 用例断言请求次数；18081 环境人工计时写入证据。

**AC-13 任务池按主题筛选与行内归主题（P1）**
- 任务池筛选条新增「主题」（含「未归主题」），条件由 `ThemeFilterSql.append()` 单点实现，与甘特分组口径一致；筛选写入 URL query（可分享、可回退）。
- 任务池新增「主题」列：ADMIN 行内可改、OWNER/EXEC 只读；行内保存失败 422 回填到该行，行不消失、列表不整页刷新。
- 无筛选时任务池 / 看板 / 矩阵计数与 r6 基线逐项相同（新增筛选不得改变默认口径）。
- 验证：「未归主题」筛选结果条数 == 甘特未归主题条数；无筛选计数与基线一致。

**AC-14 回归与真机闭环（P1）**
- web 全量 ≥ 202 例（原 188 + 新增 ≥14）全绿，`npm run typecheck`、`npm run build` 通过；server ≥ 256 例（原 248 + 新增 ≥8）全绿。
- 18081 + 5174 真机走通：建会（含 2 条决议、选主持人/参会人）→ 一键转任务（挂主题、计划开始）→ 任务开始 / 提交 / 验收 → 打开甘特按主题查看 → 「仅看逾期与风险」定位 → 任务池按主题筛选 → 回会议详情看聚合进度；留修复前后截图与接口响应，证据写入本任务夹。
- 既有口径不回退：任务池 / 看板 / 矩阵 / 通知 / CSPR 用例全部通过（含 r6 的 11 条 spec）。

## 3. 范围与非目标

**范围内**
- 会议：人员选择器、建会批量录决议项、详情连续录入、任务进度聚合区、按角色的会议跳转。
- 任务：五步闭环条、计划开始日期、主题绑定（三个入口）、风险口径、任务池主题筛选与行内归主题。
- 甘特：`/gantt` 页面、主题/项目两级分组、三档缩放、摘要与风险筛选、截断与空态。
- 数据：Flyway V7 新增 `themes` 表、`tasks.theme_id`、`tasks.planned_start_date` 及索引；不新增任务状态。

**口径决定（由约束推导，不再另问）**
- **「归档」不新增状态**：状态机固定为 `PENDING / IN_PROGRESS / PENDING_ACCEPT / DONE / CANCELLED`（`V1__schema.sql:97`）。会议层「归档」沿用 `meetings.archived`；任务层「归档」= `DONE` 后的历史视图（任务池「已完成」筛选 + 甘特「显示已完成」开关），**不引入 `ARCHIVED`**，以免看板/矩阵/日报计数分裂。
- **条终点只认 `due_date`**：不新增计划结束日期，避免甘特终点与逾期口径出现两个日期。
- **主题是归类维度不是权限维度**：与项目同构，全员可读，仅 ADMIN 维护。

**非目标**
- 甘特不做拖拽改期、任务依赖线、关键路径、资源负载/工时。
- 不导出甘特 PNG/Excel，不做甘特打印排版。
- 不向 OWNER 开放甘特；不向 EXEC 开放会议详情（见待澄清 taste 项）。
- 不做会议主题（主题只挂任务）。
- 不改任务状态机、不改「派发人验收」、不改通知/CSPR/钉钉逻辑。
- 不做任务批量改主题（行内单条足够，批量列入后续）。

## 4. 反面目标（anti-goals）

即使测试全绿、页面能开，以下任一情况都算这次失败：

1. **甘特打开后一半以上的任务挤在「未归主题」一行**。历史任务全部无主题，如果只加了字段没有补齐路径，主管看到的是「一行巨长的灰条 + 若干空行」，等于没有主题视图。可检查：任取首屏任务，未归主题占比 ≥50% 即失败。
2. **平移时间窗后逾期任务消失了**。主管往下一屏一翻，风险从图上消失，据此判断「这块没问题」。可检查：任何逾期未完成的任务，在任何时间窗下都必须可见（贴在窗口左边界），一条不可见即失败。
3. **同一个任务在甘特和看板给出不同的逾期结论**。甘特显示「逾期 2 天」，看板显示「未逾期」或逾期天数不同——口径分裂比没有甘特更糟。可检查：随机抽 5 条任务逐处比对。
4. **为了让甘特有起点，静默给历史任务补了一个开始日期**。图上进度看起来比真实更早或更晚，而用户无从知道这个日期是编的。可检查：未填计划开始的任务，条上必须有「按创建日推算」标记；数据库 `planned_start_date` 不得被回填。
5. **为了让主持人「必须选系统用户」，把历史会议的自由文本主持人在保存时清空或改名**。老会议一点保存就丢人。可检查：抽 3 条历史会议，仅修改备注后保存，`host` 文本逐字不变。
6. **300 条任务时切档或翻屏卡住超过 3 秒、或整页白屏**。图能截图但没人愿意用。可检查：18081 环境 300 条数据下人工计时。

## 5. 交互流程摘要

1. **建会（一次填完）**：`会议与决议 → 新建`：标题/日期 → 选主持人（自动进参会人）→ 搜人加参会人 → 展开「决议事项」加 2–5 行 → 提交 → 直接落在会议详情，N 条决议可勾选转任务。
2. **转任务（带主题）**：会议详情勾选决议项 → 「转为任务」→ 转任务表单可改负责人/截止/主题/计划开始 → 提交后每行状态变为「已转」并可直接跳到任务详情。
3. **闭环**：任务详情五步条 + 「下一步」提示 → 负责人开始 / 提交 → 派发人验收 → 完成；「来源」区可回看会议（ADMIN）。
4. **看全局**：`进度甘特` 默认周档 12 周 → 主题主行 / 项目子行 → 点「风险 N」只看风险 → 点条进任务详情 → 需要补主题时去任务池按「未归主题」筛出并行内设置。

## 7. 依赖与风险

**依赖**
- r1 的会议/决议/转任务契约与状态机、r4 的三态互斥与项目主数据、r6 的 422 逐字段回填口径，全部按基线不回归。

- 甘特需新增一次聚合查询（窗口 + 分组）；现有看板聚合接口不改造，仅复用其逾期与风险口径。

**风险**
1. 历史任务 100% 无主题 → 首屏「未归主题」单行：缓解 = 甘特顶部「未归主题 N 条（覆盖率 x%）」提示 + AC-13 任务池行内归主题路径。
2. 自研 SVG 的工作量（`web/package.json` 无图表库且不引入新依赖）：范围收敛为「刻度尺 + 分组行 + 绝对定位条 + 折叠」，不做拖拽与依赖线；若实现超期，月档可退化为只读缩略。
3. 时间口径失真：计划开始为空时按创建日推算，可能与真实开工不符 → 条上必须标注推算标记，且不回写数据库。
4. 会议详情权限：EXEC/OWNER 无法进入会议详情，因此任务→会议跳转必须按角色渲染，否则新增的「回看会议」入口会变成新的 403 死路（AC-5）。
5. 甘特数据量：300 条上限若与线上未完成任务数冲突，见待澄清 fact 项。

## 10. 假设与待澄清

- **（决策一 · taste）甘特默认「周档 · 12 周窗口」**：理由是一次屏宽能放下一个季度且刻度不挤。若你更想先看「月档 · 6 个月」，首屏主题条更短、趋势更明显，但单条任务会细到看不清；对应 AC-10 的刻度与翻屏断言要改。
- **（决策二 · taste）甘特默认显示已完成任务，可手动关闭**：理由是主管需要看到「做完的比例」而不是只看到剩余。若默认隐藏，首屏更干净但会误读为「这条线没产出」；影响 AC-11 的摘要与 AC-12 的条数上限。
- **（决策三 · taste）新建任务不强制填主题**：理由是兼容历史任务与快速录入，靠甘特顶部覆盖率提示 + 任务池行内补主题来收敛。若改为必填，历史任务编辑会被卡住（必须先批量归主题），但「未归主题」大行会更快消失；影响 AC-9 与 AC-13。
- **（决策四 · taste）EXEC 不能下钻会议详情**：任务是可看的，但会议详情（含全部参会人与决议）保持仅 ADMIN。若你希望主管从甘特点进会议看原始决议，需要放开 `/meetings/:id` 的 EXEC 只读（权限矩阵变更，影响 r1 AC-2 与 AC-5 的跳转设计）。
- **（决策五 · taste）甘特颜色沿用现有语义色**：待开始灰 / 进行中蓝 / 待验收橙 / 已完成绿 / 逾期红描边，与任务池徽标一致，主管不需要重新学一套图例。若你希望按主题配色（每条主题一个颜色），可读性更强但会与状态色打架，需要改成「主题色描边 + 状态色填充」。
- **（决策六 · fact）线上未完成任务规模未知**：AC-12 按 300 条截断。若演示/生产库窗口内任务常态超过 300，需要把上限提到 500 并同步压测，否则主管会频繁看到「已截断」提示。
- **默认口径声明（非待澄清，已由约束决定）**：「归档」= 会议 `archived` + 任务 `DONE` 历史视图，不新增 `ARCHIVED` 状态；甘特条终点只认 `due_date`；主题为归类维度、全员可读、仅 ADMIN 维护。这三条若被推翻，会连带改动看板/矩阵/日报的计数口径，属于范围变更而非本 PRD 内的调整。
