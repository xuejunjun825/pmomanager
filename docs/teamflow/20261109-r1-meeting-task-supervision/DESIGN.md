# 会议任务督办系统 · UI/UX 设计规范

> 本文件写给前端实现者：第 1 节是视觉地板（先读），第 2–4 节是页面与线框，第 5–9 节是组件、权限、H5、无障碍与文案，第 10 节是 AC 覆盖与落地顺序。
> 当前工作区为全新项目（无既有前端代码、无历史 DESIGN），本文档即首版设计系统；后续迭代在此基础上增量，不另起一套。

## 1. 视觉与质感规范（先读这一节）

### 1.1 设计基调

**一句话：这是一本会发红灯的内网督办台账，不是营销后台。**

任何页面偏离下面三条判断即视为不合格：

1. **数字是主角。** 矩阵、看板、任务池里的数字用等宽数字（`font-variant-numeric: tabular-nums`）并右对齐；装饰、渐变、插画不得比数字更抢眼。数据刷新时数字**不做滚动动画**，直接替换。
2. **红色是配额资源。** 全站红色只用于「逾期」与「不可逆的破坏性操作」（取消/打回/停用）。同一行最多出现一处红色信号簇（例如「左侧 3px 红条 + 逾期 N 天」算同一簇），出现第二簇就说明设计错了。
3. **状态永远有文字。** 逾期、待验收、钉钉未配置等一切状态都用「颜色 + 文字 + 图标」三重编码，禁止只靠颜色区分（色盲与投影仪场景都要读得出来）。

质感来自三件事，而不是来自装饰：**1px 细边框 + 极轻阴影**（不做卡片堆叠）、**48px 的台账行高**（密而不挤）、**克制的一次红色**。整体观感要像一张被认真排版过的督办台账：安静、准确、可核对。

### 1.4 状态反馈（每种状态都要有可见变化）

| 状态 | 变化 | 时长 / 缓动 |
| --- | --- | --- |
| hover（行） | 背景 `--c-surface-hover` | 120ms `--ease` |
| hover（可点卡） | 边框转 `--c-primary-border`，阴影 `--sh-1 → --sh-2` | 120ms |
| hover（主按钮） | 背景 `--c-primary → --c-primary-hover` | 120ms |
| pressed | 背景再深一档（`--c-primary-active`），**不做缩放、不做位移** | 80ms |
| focus-visible | 2px `--c-primary` 外描边 + 2px 偏移（`outline-offset:2px`），键盘可见、鼠标不出现 | 即时 |
| disabled | 明确配色：底 `--c-line-soft`、字 `--c-ink-400`、`cursor:not-allowed`；**不用整体 opacity**（对比度会失控） | 即时 |
| 选中行 | 底 `--c-primary-soft` + 左侧 3px 主色条 | 120ms |
| 校验失败 | 边框 `--c-danger-border`、下方 12px 红字、`aria-invalid="true"`；不抖动 | 即时 |
| 逾期行 | `inset 3px 0 0 var(--c-danger)` + 逾期 Pill；无闪烁、无呼吸灯 | 即时 |
| 催办成功 | 按钮文案变「已催办 · 刚刚」并禁用 10 分钟；催办次数 +1；该行 600ms 高亮淡出 | 600ms |
| 保存成功 | Toast + 列表刷新 + 新行 1200ms 底色高亮（`--c-primary-soft` → 白） | 1200ms |

**持久可见信息**：任务标题、负责人、截止日期、状态、逾期天数在**任何**状态下都必须同屏可见（含 hover、展开、加载完成后）；不得用 hover 才显示的 tooltip 承载这些核心字段。

### 1.5 动效

- 只做四类：hover/pressed 变色（80–120ms）、下拉与 Toast 出入（180ms，位移 8px + 淡入）、抽屉/模态出入（240ms，抽屉从右侧平移）、骨架 shimmer（1.2s 循环，线性）。
- 统一缓动 `--ease`；**禁止**回弹、旋转、页面转场、数字滚动、列表逐项飞入。
- 数据刷新：数字与徽标直接替换，不做过渡；表格整表刷新时用骨架，不用整页 spinner。
- `prefers-reduced-motion: reduce` 时：关闭 shimmer、平移动画，仅保留 ≤100ms 的颜色变化。

**空 / 加载 / 错误三态**（每个数据区块都要实现，缺一不可）：

- 加载：表格 8 行骨架（行高 48，灰块 `--c-line-soft`，圆角 4）；卡片 6 块骨架。按钮内加载用 16px 环形 spinner + 保留原文案（如「保存中…」）并锁定宽度。
- 空：48px 线性图标（`--c-ink-400`）+ 一行 14/600 标题 + 一行 13 灰说明 + 一个明确的下一步按钮（如「清除筛选」「新建任务」）。空表不出现表头以下的大片空白。
- 错误：区块内提示卡（`--c-danger-soft` 底、`--c-danger-text` 字）+「重试」按钮；不弹全局错误框，不吞掉错误。

### 1.6 数字与排版规则

- 所有计数、天数、百分比：`font-variant-numeric: tabular-nums`；表格数字列**右对齐**，文字列左对齐。
- 千分位仅在 ≥10000 时使用（`12,480`）；0 值在矩阵中显示 `0` 且为 `--c-ink-400`、不可点；分母为 0 的比率显示 `—`（不是 0%）。
- 百分比 1 位小数（`12.5%`），百分比文字**放在进度条外侧**，条形内部不嵌文字（窄条会裁字）。
- 大数字自适应：KPI 数字 `font-size: clamp(26px, 2.2vw, 32px)`，保证 5 位以上数字不撑破卡片（见 1.7）。
- 时间：日期 `YYYY-MM-DD`；同年时间 `MM-DD HH:mm`；跨年 `YYYY-MM-DD HH:mm`；通知列表 24 小时内可用相对时间（「3 分钟前」）。
- **前端不得自行推算「今天/逾期」**：接口返回 `is_overdue`、`overdue_days`、`due_soon`，前端只负责展示。这样三个页面的红灯天然一致（AC-11/AC-17）。

### 1.8 本产品的反面清单（出现即返工）

- ❌ 营销式大标题、渐变背景、插画空状态、每屏都在"讲故事"。
- ❌ 红色用于普通强调（如"新建"按钮、普通标签），导致红灯失效。
- ❌ 用颜色块代替数字（矩阵只给色块、看板只给环形图而不给数值）。
- ❌ 逾期行闪烁 / 呼吸灯 / 每 5 秒刷新（红是状态，不是警报灯）。
- ❌ 催办点完没有任何可见变化，或连点产生多条记录。
- ❌ 钉钉未配置时弹红色错误框或转圈卡死；正确做法是中性灰「钉钉未配置」+ 站内已发。
- ❌ 表格里放「操作」列塞满图标按钮（本系统操作在详情/看板，任务池行只负责跳转）。
- ❌ 抽屉/弹窗里再套弹窗；删除类确认用原生 `confirm()`。
- ❌ 只靠 hover 才显示负责人、截止日期等核心字段。
- ❌ 矩阵把逾期任务同时计入原状态列（这是本产品的头号信任杀手）。

## 2. 信息架构

### 2.1 导航结构（按角色过滤）

```
工作台
  ├ 督办看板      /dashboard     admin / exec
  └ 闭环矩阵      /matrix        admin / exec
任务
  ├ 任务池        /tasks         admin
  └ 我的任务      /my            owner（admin 也可看自己名下任务）
会议
  └ 会议与决议    /meetings      admin
通知中心          /notifications 全部角色（仅本人）
系统
  ├ 用户与角色    /users         admin
  └ 系统设置      /settings      admin
```

- 侧栏只显示当前角色有权限的项；**隐藏菜单不是安全措施**，接口仍按 AC-2 校验，越权返回 403/404。
- 通知入口在顶栏（铃铛 + 未读角标）与侧栏（带未读角标）二选一，本设计**固定顶栏**，侧栏不再重复。
- 登录后落地页：admin → `/tasks`；owner → `/my`；exec → `/dashboard`。

### 2.2 路由与角色

| 路由 | 页面 | admin | owner | exec | 说明 |
| --- | --- | --- | --- | --- | --- |
| `/login` | 登录 | ✓ | ✓ | ✓ | 未登录唯一可达页 |
| `/tasks` | 任务池 | ✓ | 403 | ✓ 只读 | owner 直接访问 → 403 |
| `/tasks/:id` | 任务详情 | ✓ | 仅本人 | ✓ 只读 | owner 访问他人 → **404**（不泄露存在性） |
| `/my` | 我的任务 | ✓ | ✓ | — | owner 主战场 |
| `/meetings` | 会议列表 | ✓ | 403 | 403 | |
| `/meetings/:id` | 会议详情 | ✓ | 403 | 403 | 任务详情可跳转，但跳转后仍校验 |
| `/matrix` | 闭环矩阵 | ✓ | 403 | ✓ | |
| `/dashboard` | 督办看板 | ✓ | 403 | ✓ | |
| `/notifications` | 通知中心 | ✓ | ✓ | ✓ | 仅本人通知 |
| `/users` | 用户与角色 | ✓ | 403 | 403 | |
| `/settings` | 系统设置 | ✓ | 403 | 403 | |
| `/403`、`/404`、`/503`、`/500` | 异常页 | ✓ | ✓ | ✓ | 503 仅钉钉回调路由 |

### 2.3 页面清单（实现范围）

12 个业务页：登录、任务池、我的任务、任务详情、会议列表、会议详情、闭环矩阵、督办看板、通知中心、用户与角色、系统设置、首次登录改密；3 个异常页：403 / 404 / 503（钉钉未配置）。**草图/线框不在本轮交付**（无美术资源），第 4 节的结构描述即实现依据。

## 4. 关键页面线框（布局 / 组件 / 状态）

### 4.1 登录 `/login`

```
                 ┌──────────────────────────────┐
                 │ ◼ 督办系统                    │
                 │ 登录                          │
                 │ 使用钉钉或账号密码进入          │
```

1. **督办日报收件人**：可搜索多选（已选以 chips 展示，可删）；已选 0 时块顶出现琥珀 banner「未配置收件人，日报/周报将不会发送」；提示「建议 1–5 人」；保存后 Toast + 留痕说明。
2. **报表开关**：日报开关 + 发送时间（默认 18:00）；周报开关 + 发送时间（默认周一 09:00）；关闭时就地说明「关闭后不发送，站内不受影响」。
3. **钉钉配置状态**：总览徽标（已配置 / 未配置）；缺失项清单（CorpId / AgentId / AppKey / AppSecret / 回调域名 / 工作通知权限）逐项 ✓ 或「缺失」；密钥**永不回显**，仅显示「已配置」；说明「由部署配置提供，页面不可编辑」。
- 变更后底部出现 sticky 保存条（56），保存成功消失；离开有未保存变更时二次确认。

### 4.12 用户与角色 `/users`

- 表格：姓名（头像 + 姓名）/ 登录账号 140 / 钉钉绑定 120（已绑定 · 尾号 4 位 / 未绑定）/ 角色 110（徽标，可改）/ 状态 96（启用/停用开关）/ 最近登录 140 / 操作 96（重置密码）。
- 角色修改：480 模态单选三角色 + 「角色变更立即生效」提示；停用：确认模态说明「停用后该用户无法登录（含钉钉），名下任务保留」。
- 重置密码：结果模态展示临时密码一次 + 复制按钮 + 「仅显示一次」提示。

## 6. 权限的界面表现（与 AC-2 对齐）

原则：**角色永远没有的能力 → 直接不渲染入口；当前条件下不可用 → 渲染但禁用并给出原因**（不用悬浮提示承载唯一解释）。

| 动作 | admin | owner（本人） | exec | 界面表现 |
| --- | --- | --- | --- | --- |
| 新建任务 / 建会议 / 录决议 / 转任务 | ✓ | — | — | 仅 admin 渲染主按钮 |
| 开始 | ✓ | ✓ | — | owner 卡片与详情主按钮 |
| 提交验收 | ✓ 代提交 | ✓ | — | 主按钮；表单 480 模态 |
| 验收通过 / 打回 | ✓ 全部 | 仅其派发 | — | 主按钮 +「打回」危险；exec 不渲染 |
| 取消 / 恢复 / 代确认完成 | ✓ | — | — | 「更多」下拉内；原因必填 |
| 改派 / 改期 | ✓ | — | ✓ | 详情与看板行内；原因必填 |
| 催办 | ✓ | — | ✓ | 已完成/已取消 → 禁用 +「任务已结束」；10 分钟内 → 禁用 +「已于 HH:mm 催办过」 |
| 矩阵 / 看板 | ✓ | — | ✓ | owner 侧栏不出现 |
| 系统设置 / 用户管理 | ✓ | — | — | owner/exec 侧栏不出现 |

- 越权页面 → 403 页；owner 按 id 访问他人任务 → **404 页**（与不存在一致，防探测）。
- 接口返回 403/404 时，前端统一落到对应异常页，不弹原始 JSON。

## 7. 响应式与 H5（钉钉内打开）

- 桌面优先，最小支持 1280×720；1280 下所有表格不横向滚动（1.7 已核算）。
- 断点：≥1440 六列 KPI；1200–1439 三列；1024–1199 两列；<1024 侧栏折叠为图标；<768 进入 H5 模式。
- H5（375 宽，钉钉内打开）**只保证看板与任务详情可读可用**（PRD 非目标允许）：
  - 顶部 48 标题栏（返回 + 页面名），无侧栏；内容 padding 16。
  - KPI 2 列；焦点列表转卡片（标题 15/600 两行、负责人/截止/状态一行、操作按钮高 44 一列排布）。
  - 任务详情单列：状态 → 来源 → 交付 → 时间线 → 右栏字段折叠成定义列表；主操作吸底（44 高 + safe-area）。
  - 抽屉/模态在 H5 全屏；表格一律转卡片；触控目标 ≥44×44；无 hover 依赖。
- 200% 缩放下不出现横向滚动（表格可内部横滚，但页面不横滚）。

## 8. 无障碍要点（验收时逐条看）

1. 对比度：正文 ≥4.5:1、大字 ≥3:1；`--c-ink-400` 只用于占位、禁用与非关键图标；主色 `#1B4D8F` 对白 ≈8.4:1，红字 `#B42318` 对浅红底 ≈6:1。
2. 键盘：所有交互可 Tab 到达、顺序符合视觉顺序；抽屉/模态焦点陷阱 + Esc 关闭 + 关闭后焦点回到触发元素；表格行可点则 `tabindex="0"` 并支持 Enter。
3. 焦点可见：`:focus-visible` 2px 主色描边 + 2px 偏移，**禁止 `outline:none`**。
4. 状态不只靠颜色：逾期 = 红条 + 文字 + 图标；渠道状态 = 文案 chip。
5. 表单：label 与控件 `for/id` 关联；错误 `aria-invalid` + `aria-describedby`；提交后错误摘要可聚焦。
6. 动态反馈：Toast 用 `aria-live="polite"`；扫描/刷新不打断读屏。
7. 触控：H5 ≥44×44；相邻可点元素间距 ≥8。
8. 动效：`prefers-reduced-motion` 下关闭位移与 shimmer；无自动播放动画。
9. 语言：`<html lang="zh-CN">`；图标按钮全部 `aria-label`（如「查看通知」「关闭」）。

## 9. 文案与格式

- 状态词固定：**待开始 / 进行中 / 待验收 / 已完成 / 已取消**；逾期文案 **「逾期 N 天」**；催办 **「已催办 N 次 · 最近 M 天前」**。
- 渠道词固定：**站内 / 钉钉已送达 / 钉钉失败 / 钉钉未配置 / 未绑定钉钉**。
- 按钮用动词：「转为任务」「提交验收」「验收通过」「打回」「催办」「归档会议」「全部标为已读」；不用「确定/提交」这种空泛词（危险确认除外）。
- 反馈句式：结果 + 对象 + 下一步。例：「已通知张三（钉钉未配置，已发站内）」「该截止日期已过期，保存后将立即显示逾期」。
- 错误：说清原因与出路，不用感叹号，不甩码。例：「截止日期不能为空」「你没有该任务的查看权限」。账号不存在与密码错误同文案「账号或密码不正确」。
- 空态文案不卖萌、不用「还没有数据哦」。
