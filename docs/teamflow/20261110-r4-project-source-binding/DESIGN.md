## 1. 视觉与质感规范（先读这一节）

### 1.1 基调

**一句话：项目是个名词，不是一个彩色徽章——它永远用中性标签、永远完整可读、永远和来源分开。**

在 r1「数字是主角 / 红色是配额 / 状态永远有文字」与 r2「名称优先于颜色 / 进度是内容 / @ 用主色」之上，本轮再加三条，违反即返工：

1. **中性是项目的唯一身份。** 项目标签统一 `--c-line-soft` 底 + `--c-ink-600` 字 + `--c-line` 边，**不参与 8 色来源色板**（PRD 非目标：不做项目颜色）。任何给项目配色的实现视为越界。
2. **名称必须完整出现在关键位置。** 详情页项目名 20 字**不截断**；列表标签允许 128px 截断但必须有 `title` 全名与「（已停用）」后缀。只显示编码 `P00001`、或只显示色块，不合格。
3. **「未指定项目」是一个明确的档，不是空白。** 它只出现在筛选与改形历史任务的展示位；在新建任务下拉里**永不出现**，在项目配置表里**永不出现**。

「项目任务（内置来源，自由说明）」「需绑定项目（形态）」「项目清单（主数据）」三件事在界面上用三个不同词：`项目任务` / `需绑定项目` / `项目`。界面任何位置不出现裸英文 `PROJECT`。

### 1.4 动效与三态

- 只新增两类动效：下拉浮层出入（180ms）、行内保存高亮（600ms）；其余沿用 r1。
- `prefers-reduced-motion: reduce`：浮层改为直接显隐（≤100ms 颜色过渡），高亮保留但缩短到 200ms。
- **加载**：项目表格 5 行骨架（行高 48 / `--c-line-soft` / 圆角 4）；下拉浮层首次打开且 meta 未到时，列表区 3 行骨架（高 32），不显示「没有匹配」。
- **空**：
  - 项目表格空：48px 线性图标 + 「还没有项目」+ 「新建后即可在项目型来源的任务里选择」+ 主按钮「新建项目」。
  - 下拉无匹配：「没有匹配的项目」+ 文本按钮「清除搜索」（focus 留在搜索框）。
  - 建任务抽屉无可用项目：「还没有可用项目。请联系管理员在「系统设置 → 项目配置」添加项目。」+ 下拉 disabled（不隐藏字段，避免表单项跳动）。
  - 筛选后无任务：沿用列表空态，标题「该项目下暂无任务」/「未指定项目下暂无任务」，副文案「换一个项目，或清除项目筛选」，按钮「清除项目筛选」。
- **错误**：区块内 `--c-danger-soft` 提示卡 + 「重试」；行内操作失败只 Toast + 回滚，不弹全局框。

### 2.2 投影与数据契约 `[新增]`

**唯一投影**（`web/src/utils/projectOptions.ts`，镜像 r3 `sourceOptions` 的形态）：

```ts
export interface ProjectOption { label: string; value: string }
export interface ProjectOptionsConfig {
  allOption?: boolean        // 首位插「全部项目」，筛选传 true（默认 true）
  includeDisabled?: boolean  // 保留停用项目并加「（已停用）」，筛选默认 true；抽屉传 false
  includeUnassigned?: boolean // 末尾追加「未指定项目」，仅筛选传 true（默认 false）
}
export function projectOptions(
  projects: ProjectOptionRow[] | null | undefined,
  config?: ProjectOptionsConfig,
): ProjectOption[]
```

- 排序：**启用在前、停用在后，组内按 `sort` 升序，同值按 id 升序**；入参先复制再排序，绝不就地排序。
- 值域：`''` = 全部项目；`'none'` = 未指定项目（哨兵，不与数字 id 冲突）；其余为项目 id 的字符串。
- 文案：停用追加 `（已停用）`；未指定项固定 `未指定项目`；**任何选项不带编码**。
- 抽屉调用 `projectOptions(projects, { allOption:false, includeDisabled:false })`；任务池/矩阵/看板调用 `{ allOption:true, includeDisabled:true, includeUnassigned:true }`。
- **「未指定项目」常驻筛选**（即使当前无项目型来源）：选项不随某条来源配置变化而跳动；选中后可为空结果，由空态解释。
- 项目列表来源：`meta` 下发 `projects: [{id,name,enabled,sort}]`（读接口，全员可读）。前端不缓存第二份、不在页面内过滤启用态（除抽屉）。

## 4. 组件规范增量

### 4.1 `AppSearchSelect` `[新增]`

Props：`modelValue: string`、`options: {label:string;value:string;disabled?:boolean}[]`、`label?`、`placeholder?`、`size?: 'compact'|'default'`、`disabled?`、`invalid?`、`error?`、`hint?`、`required?`、`id?`、`emptyText?`。
Emits：`update:modelValue`、`change`。
约束：受控组件，不做内部选中态；不 import 页面；不依赖 `meta`（选项由调用方投影好传入）。

### 4.2 `ProjectTag` `[新增]`

Props：`name?: string|null`、`enabled?: boolean`、`unspecified?: boolean`。
渲染规则：`unspecified` → 「未指定项目」；`name` 空且非 unspecified → 不渲染（`v-if` 在父级）；`enabled === false` → 名称 + 「（已停用）」。`max-width:128px`，`title` 全名。

### 4.3 `ProjectConfigTable` / `ProjectFormModal` `[新增]`

- Table：props `items/loading/error/limitReached`；emit `refresh`；行内 PATCH 成功局部替换该行（不整表闪烁），失败回滚。删除仅 usage=0 渲染；`ConfirmDialog` 二次确认。
- Modal：props `open/row`；emit `close/saved`；本地草稿，关闭丢弃；字段错误由 `fieldErrors` 映射（`name/sort`），上限与 409 走顶部摘要条。

## 7. 无障碍要点 `[增量]`

1. 项目下拉必须是 `combobox + listbox` 语义，不是「一个 input 加一堆 div」；`aria-expanded/aria-controls/aria-activedescendant/aria-selected` 齐全。
2. 「已停用」以**文字后缀**表达，不只靠灰色；停用选项 `aria-disabled="true"` 且键盘跳过。
3. 行内排序输入有 `aria-label`（含项目名），保存失败用 `role="alert"` Toast，不静默回滚。
4. 详情项目链接焦点可见（2px 主色外描边），文案包含项目名（不要「查看」这类无语境链接）。
5. 表格 `<th scope="col">` 齐全，编码列 `--font-num` 但朗读为文本；引用条数用 `N 条` 而非纯数字。
6. 弹窗：`aria-labelledby` 标题、`role="dialog" aria-modal="true"`、焦点环内、Esc 关闭（沿用 r1 既有 Modal）。
7. 改形勾选框用原生 `checkbox` + label（点击整行可勾），不自定义控件。
8. 对比度：项目标签 `#475467` on `#F2F4F7` ≈ 7.6:1；停用后缀 `#98A2B3` 仅作辅助信息（主名称已可读），不承载唯一语义。

**落地顺序（前端）**：`projectOptions` + `types` → `ProjectTag`/`AppSearchSelect` → 设置页卡片与弹窗 → 来源弹窗三选一 + 改形提示 → 抽屉 → 筛选条/矩阵/看板 → 表格与详情 → 空/错/骨架三态补齐 → 1280/1180/768 三个断点实测。

**实现备注（给开发）**：① `useQuerySync` 的 `project` 键同时接受数字与 `none`，建议值类型为 `string`（`'' | 'none' | '<id>'`），请求参数由 `buildFilter` 决定，避免为 `none` 另开布尔字段；② 三处筛选的选项必须来自一次 `projectOptions` 调用（可缓存到 meta store 的 computed），页面不得再过滤停用项；③ 项目接口只回 `id/name/enabled/sort`，配置表所需的 `usageCount` 只出现在管理端列表接口，两个模型不要混用。
