# PRD · 项目来源绑定与项目配置

## 1. 背景与目标

现状：来源形态只有两种，硬编码在 `server/src/main/java/com/pmo/supervise/source/SourceForm.java:8-9`（`MEETING` 需绑定会议、`NOTE` 自由说明），库层 `server/src/main/resources/db/migration/V4__source_types.sql:16` 用 `ck_source_form CHECK (form IN ('MEETING','NOTE'))` 固化。内置来源「项目任务」编码为 `PROJECT`（`V4__source_types.sql:23`），但形态是 `NOTE`——用户选了「项目任务」只能手写一段文字说明，系统里既没有项目实体，也没有任何项目清单；同一段项目名被 12 条任务手写成 5 种写法，无法按项目汇总，也无法回答「这个项目下有多少条督办任务」。

本轮要做两件事：

1. **项目成为可维护的主数据**：管理员在系统设置里维护项目清单（名称唯一、系统编码、启停、排序、被引用只能停用）。项目是主数据，不是权限数据——全员可选择，仅管理员可维护。
2. **项目型来源 = 绑项目**：来源形态新增第三种「需绑定项目」，与「需绑定会议」完全对称：选中它，建任务必须从项目清单里挑一个项目；任务详情、列表、任务池/矩阵/看板筛选都按这个项目走同一份数据。

成功标准：管理员新建项目「城市更新一期」、把来源「客户投诉」改成项目型后，派发人无需重启即可用它建一条绑该项目的新任务；任务池按「项目=城市更新一期」筛出 3 条，矩阵与看板同一筛选同样是 3 条；详情页点项目名回到任务池并保持该筛选。

## 2. 范围与非目标

**范围**
- 项目主数据：`projects` 表与迁移、管理员维护卡片（系统设置页第五块卡片）、启停/排序/引用护栏、审计。
- 来源形态第三态：`SourceForm` 增加 `PROJECT`，配置页形态单选扩为三选一，库层 CHECK 扩为三值，建任务表单出现「来源项目」必选项与三层校验。
- 任务落库与展示：`tasks.source_project_id`、任务详情来源区项目名、任务列表/卡片项目标签。
- 筛选项：任务池筛选条、闭环矩阵、督办看板三处新增「项目」下拉，选项单一投影。
- 改形兼容：已有任务的来源改为项目型时的历史数据处理与「未指定项目」口径。

**非目标（本轮不做）**
- 不做项目详情页、项目成员、项目进度百分比/甘特/里程碑、项目预算与合同。
- 不做项目层级（子项目、项目群）、不做项目标签体系、不做项目颜色配置（项目标签统一中性样式，不参与配色）。
- 不做项目导入导出、不做批量建项目、不做项目合并/重命名级联（改名即回溯全站显示，无逐任务快照）。
- 不改会议侧任何行为：会议/决议项/一键转任务、会议型来源的表单与校验保持不变。
- 不改钉钉集成范围（不把项目写进日报/周报/工作通知正文），不改状态机五状态与 18 条迁移，不改逾期口径与矩阵/看板/日报指标定义。
- 不做「项目必填」的全局强制：项目只对项目型来源必填，说明型来源不因本轮变为必绑项目。

## 3. 反面目标（anti-goals）

技术上跑通、测试全绿，但下面任意一条发生，人就会判定这次交付失败：

1. **「项目」一词三义，用户选错还看不出来**：内置来源「项目任务」（自由说明）、新形态「需绑定项目」、项目配置清单，三件不同的事共用一个词。可观察：找一位没读过文档的同事建一条项目型任务——如果他问「项目在哪选」，或提交成功后任务列表的项目列是空的、只有一段手写说明，即失败。
2. **历史任务被改形成坏数据**：管理员把「客户投诉」从说明型改成项目型后，12 条历史任务的项目列显示空白或「—」，原来的说明文字在详情里消失，按「未指定项目」也筛不出来。可观察：改形后打开任意一条历史任务，看不到它原来的来源说明。
3. **停用项目让历史任务失去身份**：停用一个被 12 条任务引用的项目后，这 12 条任务的列表与详情里项目名变成「未知项目」或直接消失，按该项目筛选查不到任何东西。可观察：停用前后同一批任务的列表逐行对比，项目列不一致。
4. **三处口径不一致**：任务池按「项目=城市更新一期」筛出 37 条，矩阵同一筛选行合计 40（差的 3 条是没有项目的历史任务），看板又是 39。可观察：同一天、同一筛选组合，三处数字对不上。
5. **项目多了选不到**：项目数超过下拉可承载量后，派发人翻不到目标项目、也没有搜索框；或新建第 201 个项目直接失败而页面没有任何提示。可观察：让用户在 120 个项目的清单里找「城市更新一期」，超过 30 秒或必须靠浏览器 Ctrl+F 即失败。

## 4. 用户故事与验收标准

### US-1 管理员维护项目清单（P0）

作为管理员，我要在系统设置里维护一张项目清单，让派发人建任务时能选到「城市更新一期」这样的真实项目，而不是各写各的。

**AC-1 项目配置卡片**
- 系统设置页在「来源配置」卡片（`web/src/pages/SettingsPage.vue:417`）之后新增「项目配置」卡片，仅管理员可见可操作，文案说明「项目是任务来源的可选绑定对象；行内改动即时生效」。列表列：名称、编码（只读）、状态、排序、被引用任务数、操作。
- 新增/编辑弹窗字段：名称（必填，2–20 字，去首尾空格后按 Unicode 码点计数）、编码（只读，新建时显示「保存后自动生成」，形如 `P00001`，创建后不可修改，不接受手填）、排序（0–99）、启用开关。
- 名称全表唯一（含已停用项目）：重名返回 409 并在名称字段回显「名称已存在，请换一个」；长度越界返回 422，`fieldErrors.name` 给出「名称为 2–20 字」。
- 项目总数上限 200（含已停用）：新建第 201 个返回 409「项目最多 200 个」，页面在达上限时把「新建项目」置灰并给出提示（不静默失败）。
- 排序与启停为行内即时生效，无整页「保存」；排序值 0–99 越界拒绝。变更后其他页面刷新一次即读到新清单，无需重启。

**AC-4 删除与停用的护栏**
- 被任意任务引用（含已取消、已验收状态）的项目不可物理删除，返回 409「该项目已被 N 条任务使用，只能停用」；未被引用可删除，删除前二次确认并显示「删除后不可恢复」。
- 停用后：新建/编辑任务的项目下拉中不出现；即使构造请求提交停用项目也返回 400「该项目已停用，请重新选择」；历史任务详情与列表仍显示项目名并带「（已停用）」标注；任务池/矩阵/看板按该项目筛选仍能筛出历史任务。
- 重新启用后立即回到新建下拉，并按排序值归位；停用不改变任何任务的 `source_project_id`。

**AC-8 权限与审计**
- 项目清单读：所有已登录用户可读启用项目与历史项目名（供建任务下拉、筛选、详情展示），接口只回传 `id / name / enabled / sort`，不含引用数与任何操作信息。
- 项目写（新增/编辑/启停/删除）：仅 `ADMIN`，非管理员调用返回 403，页面上不出现该卡片；未登录返回 401。
- 每次变更写 `audit_logs`：`action` 为 `PROJECT_CREATED / PROJECT_UPDATED / PROJECT_ENABLED / PROJECT_DISABLED / PROJECT_DELETED`，`detail` 含变更前后名称、启用状态、排序。

### US-2 派发人按项目型来源建任务（P0）

作为派发人，来源选「客户投诉（需绑定项目）」时，我要直接从项目清单里挑项目，而不是再手打一段项目名。

**AC-2 建任务按形态绑定项目**
- 来源形态扩为三值：`MEETING`（需绑定会议）/ `PROJECT`（需绑定项目）/ `NOTE`（自由说明）。配置页形态单选三选一（`web/src/components/settings/SourceTypeFormModal.vue:210` 的 radiogroup 扩为三项），库层 `ck_source_form` 的允许值同步扩为三值。
- 所选来源形态为 `PROJECT` 时，新建任务抽屉的「来源」区显示**必选**「来源项目」下拉并隐藏会议与说明字段；下拉只列启用项目、按排序值升序、文案为名称（不露编码）。缺选返回 422 且 `fieldErrors.sourceProjectId` 为「项目来源必须选择项目」；选到停用或已删除项目返回 400；携带 `sourceNote` 或会议字段返回 400「项目来源不能填写说明/不能关联会议」。
- 形态为 `MEETING` / `NOTE` 时行为与 r2/r3 完全一致（会议型必须会议 + 决议项且决议项唯一、说明型必须 1–200 字说明、三类字段两两互斥），回归用例逐条通过；会议决议一键转任务仍固定用内置会议型来源，行为不变。
- 库层兜底不放松：`tasks.source_type NOT NULL`、`source_project_id` 外键 `ON DELETE RESTRICT`、三态互斥 CHECK（会议对 / 项目 / 说明 至多一类非空），不得因为新增形态而放开互斥。
- 编辑态来源仍不可修改（含来源项目）：改项目要走「来源不可修改，如需更换项目请新建任务」的既有提示。

### US-3 升级与改形都不毁历史（P0）

作为已在用系统的用户和管理员，升级后历史任务的原样显示不变；管理员把某个来源改成项目型，也不能让 12 条老任务变成「坏数据」。

**AC-3 升级兼容**
- 迁移只做加法：新增 `projects` 表与 `tasks.source_project_id`（可空），扩展形态约束；**不改写任何 `tasks` 行**、不新增内置来源、不改变既有三条内置来源的编码/名称/颜色/形态（「项目任务」`PROJECT` 仍是自由说明，不自动变成项目型）。
- 升级后历史任务在任务池、详情、矩阵、看板、筛选中的来源显示与筛选结果与升级前逐项一致（同一批任务升级前后接口对照无差异）；历史任务的项目列为空，不显示「未指定项目」、不报错（该占位只用于 AC-6 的改形场景）。
- 形态为项目型的来源在配置页形态列显示「需绑定项目」，与「需绑定会议」对称；内置「项目任务」来源名称保持不变，其形态列显示「自由说明」，避免与项目清单混淆。

**AC-6 来源改形为项目型的历史兼容**
- 管理员可把已有任务的 `NOTE` 来源改为 `PROJECT`：允许，弹窗需提示影响面「该来源已有 N 条历史任务，改形后不迁移历史数据，它们将显示为「未指定项目」」，二次确认后生效。
- 改形不迁移、不改写任何历史任务数据（`source_note` 保留原文、`source_project_id` 保持空、状态与 `task_events` 不变）；这些任务在任务详情与列表的项目位显示中性占位「未指定项目」，来源说明照旧展示。
- 任务池/矩阵/看板的项目筛选提供「未指定项目」选项，选中后精确返回「来源形态已是项目型、但任务本身无项目」的历史任务，且与 AC-5 的过滤谓词同源。
- 反向改形（项目型改回说明型）同样不迁移数据：历史任务的项目照旧展示，不伪造说明。内置会议决议形态仍锁定不可改（沿用 r2 规则）。

### US-4 一处配置，处处同源（P0）

作为用筛选条找任务的人，我要在任务池、矩阵、看板上都能按项目筛，且三处永远同一份项目清单、同一个口径。

**AC-5 项目筛选同源一致**
- 任务池筛选条（`web/src/components/task/TaskFilterBar.vue:164-172` 来源/会议之后）、闭环矩阵、督办看板的筛选区各新增「项目」下拉；选项 = 全部项目（启用在前按排序、停用在后并带「（已停用）」，末尾追加「未指定项目」），与「来源」筛选同级、可与其他筛选组合。
- 项目下拉选项必须由**单一投影实现**产生（沿用 r3 收口的 `sourceOptions` 模式，三处调用同一函数，页面不得各自拼装）；新增项目后刷新三处同时出现，不需要重启或改代码。
- 筛选参数按项目 id 精确匹配，未知/已删除 id 返回 400 且提示「项目不合法」，与来源筛选的错误口径一致；不带项目参数时结果集与升级前完全一致。
- 同一筛选组合下任务池总条数 = 矩阵行合计（不含取消的既有口径）= 看板对应计数，「未指定项目」作为独立一档参与合计，不得被静默丢弃。

### US-5 项目在人眼前是可见的（P1）

作为打开任务的人，我要一眼看到这条任务属于哪个项目，并能顺着项目看这个项目的全部任务。

**AC-7 详情与列表展示**
- 任务详情来源区在来源标签之后展示项目名（名称上限 20 字，完整展示不截断）；点击项目名跳转到任务池并预置「项目 = 该项目」筛选（本轮无独立项目详情页）。
- 任务池/矩阵下钻列表/首页任务卡片的行内展示项目标签（中性样式，与来源标签并列、不抢色）；无项目时不渲染空标签，改形历史任务渲染「未指定项目」占位。
- 停用项目在详情与列表中显示名称 + 「（已停用）」标注，仍可点击并正确筛出历史任务。

**AC-9 口径回归**
- 项目能力不得改变任何既有口径：补进度/改派/改期/状态流转、`task_events`、逾期函数与「今天」（`ShanghaiClock.today()`）、任务池/矩阵/看板/日报/周报数字、管理层 6 项 KPI、按人闭环矩阵五列互斥与行合计 = 非取消。
- 可见性不因项目而改变：同一任务在同一筛选下，管理员、管理层、负责人、被 @ 人看到的结果与加入项目筛选之前一致（项目不是权限维度，不放宽也不收紧）。
- 钉钉与日报正文不出现项目字段；未配置钉钉时的降级行为（跳过推送、不阻断业务、不 500）不变。

## 5. 交互流程摘要

1. 管理员进「系统设置 → 项目配置」→ 新建「城市更新一期」（名称 6 字，编码自动 `P00001`，排序 10）→ 行内启用。
2. 管理员进「来源配置」→ 编辑「客户投诉」→ 形态选「需绑定项目」→ 若已有引用，弹窗提示「已有 12 条历史任务，改形后显示为『未指定项目』」→ 确认保存。
3. 派发人点「新建任务」→ 来源选「客户投诉」→ 表单出现必选「来源项目」→ 选「城市更新一期」→ 填标题/负责人/截止时间 → 保存成功。
4. 任务池：该行出现项目标签；筛选「项目 = 城市更新一期」→ 3 条；矩阵与看板同一筛选同样 3 条；筛选「未指定项目」→ 12 条历史任务。
5. 打开任务详情 → 来源区显示「客户投诉 · 城市更新一期」→ 点项目名 → 回到任务池且筛选已预置为该 项目。
6. 停用「城市更新一期」→ 新建下拉里不再出现；历史任务的 3 条记录仍显示「城市更新一期（已停用）」并可筛出。

## 6. 优先级

| AC | 主题 | 优先级 |
|---|---|---|
| AC-1 / AC-4 / AC-8 | 项目配置卡片、删除停用护栏、权限与审计 | P0 |
| AC-2 | 建任务按项目形态绑定项目（含三态互斥与三层校验） | P0 |
| AC-3 / AC-6 | 升级兼容、改形历史兼容（「未指定项目」口径） | P0 |
| AC-5 | 项目筛选同源一致（三处一处投影、同口径合计） | P0 |
| AC-7 / AC-9 | 详情与列表展示跳转、口径回归 | P1 |

P0 缺任一项视为本次需求未交付；AC-9 的回归必须随 P0 一起验证（矩阵/看板数字一旦被项目筛选带偏，交付即失败）。AC-7 可在同一迭代内随后补齐。

## 7. 依赖与风险

**依赖**
- 依赖 r2 既有能力：来源配置与形态校验单点（`server/src/main/java/com/pmo/supervise/task/TaskService.java:189-236` 的 `validateSource`）、错误码约定（`server/src/main/java/com/pmo/supervise/common/ErrorCode.java:28-33`）、审计记录、meta 选项装配（`server/src/main/java/com/pmo/supervise/meta/MetaService.java:69-75`）。
- 依赖 r3 既有能力：来源选项唯一投影 `web/src/utils/sourceOptions.ts`、详情 `SourceTag` 唯一渲染点；本项目选项投影按同一模式新增，不得回退成页面自拼。
- 数据库迁移：本需求需要一条新的 Flyway 迁移（`projects` 表、`tasks.source_project_id` 与外键、`ck_source_form` 扩三值、`ck_tasks_source` 扩三态互斥）；只加法，不改写既有数据。

**风险**
1. **词义冲突（最大风险）**：内置来源编码 `PROJECT`（名称「项目任务」，自由说明）与新形态 `PROJECT`（需绑定项目）同名不同义，代码与文案都容易混。缓解：形态中文名统一「需绑定项目」，界面不出现裸英文 `PROJECT`；`SourceForm` 的值与来源编码在实现中不得互相兜底（配置缺失时不得按同名字符串猜形态），AC-3 以「内置项目任务仍是自由说明」为回归点。
2. **互斥约束改动后库层兜底变弱**：三态互斥从两路扩到三路，若 CHECK 写成「一类非空即可」的宽松形式，非法组合（如同带说明与项目）会写进库。缓解：CHECK 保持「至多一类非空 + 会议型必须成对」，形态必填由服务端单点判定，并补非法组合的库层拒绝用例。
3. **改形后出现两套语义并存**：同一来源下既有「有项目」的新任务又有「未指定项目」的历史任务，筛选与统计若只按 `source_project_id` 过滤，会把历史任务漏掉。缓解：AC-5 以「合计对齐」为验收动作，「未指定项目」作为显式一档，不允许靠「无参数」隐式包含。
4. **筛选条横向拥挤**：任务池现在已有 类型/来源/会议/负责人/状态/逾期 等控件，再增加「项目」在 1280px 下可能换行或挤压搜索框。缓解：项目下拉与来源下拉同宽同风格，允许筛选区换行，不为塞下新控件而缩小字号或去掉已有筛选项（并入 AC-7 的视觉验收，人工复核）。
5. **项目数量增长后的选择成本**：200 上限内若无搜索，选项目会成为建任务的瓶颈（反面目标 5）。缓解：见待澄清第 4 条，默认按「可搜索下拉」实现。

## 9. 假设与待澄清

已确认前提（不作为问题）：来源形态新增「需绑定项目」；项目由管理员在系统设置维护、名称唯一 2–20 字、编码系统生成不可改、被引用只能停用；任务池/矩阵/看板增加项目筛选、详情与列表展示项目；内置「项目任务」「日常待办」保持自由说明；单实例内网、Spring Boot + Vue + MySQL + Flyway、不改钉钉集成范围——以上均为用户本轮已确认口径。

以下每条都是需要用户拍板的口径，括号内为推荐默认值与影响：

- **（口径）来源由说明型改为项目型时，历史任务怎么办**（推荐：允许改形 + 历史任务零迁移、显示「未指定项目」，因为用户明确要求「保留原来源快照或迁移到未指定项目」两条路之一，且禁止改形会逼管理员新建重复来源、把历史与新建拆成两处筛选）。若改为「有引用即拒绝改形（409，与会议型一致）」，则需要管理员先用新编码建一条项目型来源，历史任务的来源与筛选会出现两条并列记录。
- **（交互）任务详情里点项目名跳到哪里**（推荐：跳任务池并预置「项目=该项目」筛选，因为本轮没有也不做项目详情页）。若选择「不做跳转，只显示名称」，则详情页少一个入口但避免跳到别处；若选择「新建项目详情页」，本轮范围会多一个页面（项目下的任务列表 + 项目信息），需要追加设计与验收。
- **（数据）现有生产库里是否已有需要回填项目的历史任务**（推荐：不回填，历史数据保持说明型显示，因为无法从仓库判定线上数据分布；如需回填应由业务方提供「任务 → 项目」对照表，作为独立数据治理任务处理）。这是事实项：若线上确实有大量「项目任务」来源的手写说明，回填与否直接决定上线后第一周用户是否觉得「还是老样子」。
- **（范围）项目字段是否只做名称**（推荐：只做名称 + 启停 + 排序，因为增加负责人/起止日期会牵动权限、看板分组与日报口径）。若需要项目负责人，需要再定义「项目负责人是否自动成为该项目任务的可见者」。
- **（容量）项目上限与选择器形态**（推荐：上限 200、项目下拉支持输入搜索，因为超过 30 个项目后纯下拉就翻不动，直接影响建任务体验）。若上限设为 50，则大型组织需要按年度清理项目；若不做搜索，则反面目标 5 无法排除。
- **（展示）停用项目在历史任务上是否标注「（已停用）」**（推荐：标注，与来源停用的既有做法一致，让用户知道为什么选不到它了）。若选择静默显示名称，界面更干净，但用户会困惑「为什么这个项目在下拉里找不到」。
