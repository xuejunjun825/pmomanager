## 1. 视觉与质感规范 `[新增]`

### 1.1 基调

**一句话：来源是管理员起的一个名字，进度是一句写给人看的话——两者都不许抢走「数字与红灯」的主角位。**

在 r1 三条判断（数字是主角 / 红色是配额 / 状态永远有文字）之上，本轮再加三条，违反即返工：

1. **名称优先于颜色。** 任何地方展示来源，必须出现**名称文字**；颜色只是扫读锚点。只给色块、只给编码（`MEETING` / `CUSTOM_1`）都不合格。
2. **进度是内容，不是系统事件。** 进度条目不加卡片、不加边框、不用语义底色；它与流转记录共用一条 1px 竖线，视觉层级低于状态徽标与逾期 Pill。
3. **@ 用主色，不用红色。** 提及高亮 = 主色文字 + 虚线下划线；红色继续只属于逾期与破坏性操作。

来源色板是**身份色**，不承载状态语义：琥珀色来源不等于「待验收」，绿色来源不等于「已完成」。因此色板与语义色可以共用变量值，但标签形状（20 高 Tag）与状态徽标（22 高 Badge）必须保持不同，避免误读。

### 1.4 状态反馈

| 场景 | 变化 | 时长 / 缓动 |
| --- | --- | --- |
| hover 配置表行 | 底 `--c-surface-hover`；行内操作由 `--c-primary` 变 `--c-primary-hover` | 120ms `--ease` |
| hover 色块（未选） | 外环 1px → 2px `--c-ink-400` | 120ms |
| focus-visible（色块/按钮/行） | `outline:2px solid var(--c-primary); outline-offset:2px` | 即时 |
| 选中色块 | 2px 主色外环 + ✓；下方「颜色：墨蓝」同步更新 | 即时（不做颜色渐变过渡） |
| 停用/启用成功 | 状态列 Badge 立即切换；该行底 `--c-primary-soft` 1200ms → 白；Toast | 1200ms |
| 新增来源成功 | 弹窗关闭 + 新行 1200ms 高亮 + 表格滚到该行；Toast | 1200ms |
| 删除成功 | 行移除（无高度收缩动画，直接移除后表格重排） | 即时 |
| 校验失败 | 控件边框 `--c-danger-border` + 下方 12px 红字 + `aria-invalid`；不抖动 | 即时 |
| 提交进度中 | 按钮 loading 保留文案「提交中…」并锁宽；textarea 只读但文字不变；@ 按钮禁用 | 即时 |
| 进度提交成功 | 条目插入列表顶部 + 底色 `--c-primary-soft` 1200ms → 透明；输入清空、chip 清空；Toast | 1200ms |
| 进度提交失败 | 输入与 chip 原样保留；输入区下方错误条 +「重试」 | 即时 |
| 锚点定位（从通知进入） | 滚动到 `#progress-{id}` + 底色 `--hl-anchor` 1600ms → 透明；条目容器获焦（2px 焦点环） | 1600ms |
| @ 浮层出入 | 淡入 + 上移 4px；关闭反向；不使用缩放 | 180ms |
| @ 选中/取消 | 行右侧勾选即时；chip 淡出 120ms（不做宽度收缩，避免挤行） | 120ms |
| 达到 10 人上限 | 其余行 disabled（字 `--c-ink-400`），底部文案变「10 人已选满，取消一位后可继续」 | 即时 |
| 达 200 条上限 | 输入区整体禁用（**不隐藏**）：浅灰底、placeholder 换为上限说明、提交按钮禁用 | 即时 |

**持久可见**：来源**名称**、进度作者与时间、@ 人姓名，在任何状态（hover / 加载完成后 / 已结束任务）都必须同屏可见，不得只放在 `title` 悬浮提示里。

### 1.5 动效与三态

本轮只增加两类动效：**浮层出入 180ms**、**一次性的高亮淡出（1200ms / 1600ms）**。禁止：进度条目滑入、chip 飞入、来源色切换渐变、数字滚动、页面转场。

| 新增数据区块 | 加载 | 空 | 错误 |
| --- | --- | --- | --- |
| 来源配置表 | 5 行骨架（行高 56，灰块 `--c-line-soft`，圆角 4） | 逻辑上不可能为空（内置 3 条）；若接口返回 0 条，显示「内置来源缺失，请检查数据迁移」+ 重试，**不显示空态插画** | 区块内错误卡（`--c-danger-soft`）+「重试」，不弹全局框 |
| 合并时间线 | 3 条骨架（8px 圆点 + 两行灰条） | 「任务刚创建，还没有流转或进度记录」 | 区块错误卡 + 重试；状态步进与右栏不受影响 |
| @ 成员浮层 | 成员名单随详情一次性取回，无骨架；搜索为本地即时过滤 | 「没有匹配的成员」/「10 人已选满」 | 浮层内一行错误 +「重试」，浮层不自动关闭 |
| 通知中心「@我的」 | 沿用 r1 | 「还没有人 @ 你」+「被 @ 时会出现在这里」 | 沿用 r1 |

`prefers-reduced-motion: reduce` 下：关闭浮层位移与所有高亮淡出（直接呈现终态），保留 ≤100ms 的颜色变化。

### 1.6 数字与排版

- **编码**（`MEETING` / `CUSTOM_3`）用 `--font-num` 11/16、大写、`--c-ink-500`，永远与名称同格显示，不单独成列、不作为主标签。
- 计数（`3/10`、`0/500`、`14/20`）用 `tabular-nums`、12/18、`--c-ink-500`，右对齐；达到上限时字色转 `--c-warn`（不是红色）。
- 引用任务数 4 位以内，右对齐；0 显示 `0` 且为 `--c-ink-400`。
- 名称为 2–10 字：表格与详情**完整显示**（10 字 ×11px + 12 padding + 2 border = 124 ≤ 128 上限）；其他位置超过 128px 才截断，`title` 给全名。
- 正文进度 14/22、`white-space: pre-wrap`、`overflow-wrap:anywhere`；不启用富文本，不解析 Markdown。
- 时间沿用 r1：时间线 `YYYY-MM-DD HH:mm`，通知 24 小时内相对时间。

### 1.8 本产品的反面清单（本轮，出现即返工）

- ❌ 来源标签只给颜色块，或直接显示编码 `CUSTOM_1` / `MEETING`。
- ❌ 配置改了某处没刷新：建表单有、任务池筛选没有，或同名两种颜色（AC-5 的核心失败）。
- ❌ 停用来源从任务池/矩阵筛选中消失，历史任务筛不出来。
- ❌ 删除被引用来源靠接口 409 弹红框兜底——界面就不该提供可点的删除。
- ❌ 补一条进度顺手把状态从「待办」推到「进行中」，或写了一条流转记录（AC-12 头号回归）。
- ❌ 正文里手打「@张三」就被高亮、发通知、授予可见性（只有选择器选中的才算）。
- ❌ @ 选择器列出自己、停用用户，或允许第 11 个人。
- ❌ 被 @ 人看到可点的「验收通过 / 改派 / 催办」——必须整组不渲染，禁用也不合格。
- ❌ 进度条目和流转条目长得一模一样，用户分不清「系统发生了什么」和「人说了什么」。
- ❌ 已验收/已取消任务隐藏进度输入框（AC-7 明确任何状态可补）。
- ❌ @ 浮层挡住提交按钮、超出视口，或需要先滚动才能看到已选人。
- ❌ 用红色表达「@ 了你」，或用黄色底表达提及。

- **排序**：`sort` 升序，同值按 id 升序；内置 0/1/2 默认在顶部。不提供拖拽（排序值在弹窗内改，避免误拖）。
- **列语义**：来源列两行（名称 14/600 + 编码 11 mono）；形态列纯文字；颜色列 = 12px 色块 + 色名（**色名必须在**）；状态列 `AppBadge`（启用 success+dot / 已停用 neutral+dot），内置会议决议在名称下加「内置」neutral 小标签；引用列显 `N 条`；操作列见下。
- **操作**：
  - 「编辑」：所有行可用（内置也允许改名与改色）。

- **加载/错误**：5 行骨架；错误卡 + 重试。行内操作失败：该行恢复原值 + Toast（危险操作走 `ConfirmDialog`）。

## 7. 无障碍要点 `[增量]`

1. **色板**：`role="radiogroup"` + `aria-label="来源颜色"`，每块 `role="radio"` + `aria-checked` + `aria-label="颜色：墨蓝"`；方向键切换；下方「颜色：墨蓝」文本保证不靠色觉。
2. **@ 浮层**：`role="combobox"` + `aria-expanded` + `aria-controls` + `aria-activedescendant`；列表 `role="listbox"`、行 `role="option"` + `aria-selected`；Esc 关闭且焦点回 textarea；已选数 `aria-live="polite"`。
3. **进度条目**：合并列表用 `<ol>`；锚点条目 `tabindex="-1"` 并在定位后 `focus()`（焦点环可见）；新条目插入不触发整表读屏重播，结果由 Toast（`aria-live="polite"`）播报。
4. **禁用可解释**：200 条上限、20 个来源上限、10 人上限、内置不可停用——原因用可见文本承载，`title` 只作补充。
5. **表单**：沿用 r1 的 label `for/id`、`aria-invalid`、`aria-describedby`；409 的服务端文案落到对应字段，不汇总成一句「操作失败」。
6. **对比度**：来源 Tag 的 11px 文字 ≥4.5:1（§1.2 已逐色核对）；`--c-ink-400` 仍只用于占位与禁用。
7. **触控**：H5 按钮 ≥44×44；@ 行高 44；相邻可点元素间距 ≥8。

## 8. 文案（本轮固定） `[新增]`

- 来源：**来源配置 / 新增来源 / 形态 / 需绑定会议 / 自由说明 / 内置 / 已停用 / 启用 / 停用 / 引用任务数**。
- 护栏：**该来源已被 N 条任务使用，只能停用** / **来源类型最多 20 个** / **已有 N 条任务使用该来源且未绑定会议，无法改为会议型** / **编码由系统生成，创建后不可修改** / **内置来源不可停用**。
- 进度：**记录进展，输入 @ 可提醒同事…** / **@ 提及成员** / **补充进度不会改变任务状态与看板数字** / **进度已记录** / **已通知 N 位成员** / **该任务进度已达 200 条上限** / **最多 @ 10 人** / **没有匹配的成员** / **已选 N/10**。
- 通知：类型标签 **被@**；标题 **{作者} 在任务《{标题}》中@了你**；空态 **还没有人 @ 你**。
- 错误：**来源类型不合法** / **该来源已停用，请重新选择** / **你没有补充进度的权限** / **名称已存在，请换一个**。
- 句式沿用 r1「结果 + 对象 + 下一步」，不用感叹号，不甩 code。
