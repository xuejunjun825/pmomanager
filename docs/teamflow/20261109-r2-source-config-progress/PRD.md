# PRD · 来源自定义配置与任务进度 @

## 1. 背景与目标

现状（r1 已交付并运行）：`server/src/main/java/com/pmo/supervise/common/SourceType.java:9-13` 把来源写死为 `MEETING / PROJECT / DAILY`，库层 `server/src/main/resources/db/migration/V1__schema.sql:68,92-95` 用 `ck_tasks_source` 固化「MEETING 必须绑会议+决议项、PROJECT/DAILY 必须填说明」；`meta/MetaService.java:68` 直接由枚举生成下拉项，前端 `web/src/types/enums.ts:43-51`、`web/src/components/ui/SourceTag.vue` 三色固定。任务详情只有状态流转时间线（`web/src/pages/TaskDetailPage.vue:277` 的 `TransitionTimeline`），没有进度/评论能力；通知类型见 `server/src/main/java/com/pmo/supervise/common/NotifyType.java:4-12`，尚无「@ 提及」类。

两个目标：

1. **来源可配置**：来源类型成为管理员可增删改、可启停的配置项，任务创建时按配置选择；既有三类平滑迁移，历史任务显示不变。
2. **进度与 @**：任务详情内可随时追加进度记录（文字），可 @ 站内成员；被 @ 人收到站内通知（钉钉已配置时同样推送），并能打开该任务继续跟进。

成功标准：管理员新增一个来源类型后，派发人无需重启、无需改代码即可用它建任务，并在任务池/矩阵中按它筛选；负责人在详情里补一条进度 @ 两个人，两人都收到通知且能点开任务，而任务状态与看板数字一个都没变。

## 2. 范围与非目标

**范围**
- 来源类型配置：配置表与迁移、管理员维护页（系统设置内）、任务创建/编辑表单、任务池与矩阵筛选、详情与列表标签、会议决议转任务的兼容。
- 任务进度：详情页进度区（与流转时间线合并展示）、进度数据与接口、@ 成员选择、站内/钉钉通知、被 @ 人的任务可见性、权限矩阵扩展。

**非目标（本轮不做）**
- 不做进度百分比/燃尽图、不做附件与图片、不做富文本（进度为纯文本）。
- 不做评论的编辑、删除、回复嵌套、点赞、表情。
- 不做来源类型的多级分类、颜色自定义（只从固定色板选）、来源类型的导入导出。
- 不改变现有状态机五状态与 18 条迁移、不改变逾期口径与矩阵/看板/日报指标定义。
- 不做 @ 全员/角色（只 @ 具体成员），不做 @ 的撤回。
- 不做通知偏好设置（被 @ 不可关闭），不改钉钉凭证缺失时的降级契约。

## 3. 反面目标（anti-goals）

技术上跑通、测试全绿，但下面任意一条发生，人就会判定这次交付失败：

1. **升级后历史任务「认不出来源」**：老任务标签显示空白、英文 code（`MEETING`）、或「未知类型」报错，甚至旧三类在配置页消失、需要手工重建才能再建同类任务。
2. **配置改了，三处显示不一致**：新增来源后，新建表单里有它，任务池筛选里没有，矩阵筛选里又是另一个名字/颜色；同一任务在列表和详情里是两个颜色。
3. **@ 了人却收不到，或点开是 404**：通知发出去了，被 @ 人打开链接看到「任务不存在」，或通知指向了同名的另一条任务；通知中心未读角标不增加。
4. **补进度悄悄改了任务**：负责人只写了一句进度，任务从「待办」变成「进行中」，矩阵/看板的进行中与逾期数字跟着变——用户没点任何状态按钮，数字却动了。
5. **配置页能删掉在用的来源**：删除后历史任务详情 500 或来源列空白，只能改库修数据。

## 4. 用户故事与验收标准

### US-1 管理员维护来源类型（P0）

作为管理员，我要在不改代码、不重启的情况下增删改来源类型，让「客户投诉」「审计整改」这类新来源能立刻投入使用。

**AC-1 来源配置维护页**
- 系统设置页新增「来源配置」卡片，仅管理员可见可操作；列表列：名称、编码（只读展示）、形态（需绑定会议 / 自由说明）、颜色、排序、状态、被引用任务数。
- 新增：名称 2–10 字（中文/字母/数字，去首尾空格）且全表唯一，重名返回 409；形态二选一；颜色从 8 色固定色板选择；默认启用。启用类型总数上限 20（含内置 3），超限提示「来源类型最多 20 个」。
- 编辑：名称、形态、颜色、排序（0–99）可改，编码创建后不可改。把「自由说明」改为「需绑定会议」时，若已有引用任务的 `source_meeting_id` 为空，拒绝修改并返回 409，提示「已有 N 条任务使用该来源且未绑定会议，无法改为会议型」。
- 启用/停用一键切换；停用不影响历史数据展示（见 AC-4）。
- 配置变更后，其他页面刷新一次即读到新配置，无需重启服务。

**AC-4 删除与停用的护栏**
- 被引用任务数为 0 的来源可删除（物理删除配置行）；被引用时返回 409，提示「该来源已被 N 条任务使用，只能停用」。
- 停用效果：新建/编辑任务的下拉中不出现；任务池与矩阵的筛选项中仍保留（用于查历史）；任务标签与详情照常显示该来源名称与颜色；已停用的来源不能用于新建任务（接口返回 400）。
- 内置「会议决议」标记为系统内置：不可删除、不可停用（会议决议一键转任务依赖它），名称与颜色可改。

**AC-6 权限与审计**
- 非管理员调用来源配置的增/改/停用/删接口返回 403，页面上不出现该入口。
- 每次变更写 `audit_logs`：`action` 为 `SOURCE_TYPE_CREATED / SOURCE_TYPE_UPDATED / SOURCE_TYPE_DISABLED / SOURCE_TYPE_ENABLED / SOURCE_TYPE_DELETED`，`detail` 含变更前后的名称、形态、启用状态。

### US-2 派发人按配置创建任务（P0）

作为派发任务的负责人，我要在下拉里看到管理员配好的来源，并让「会议型来源必须绑会议」这条规则继续生效。

**AC-2 新建任务按配置选择来源**
- 新建任务抽屉的来源下拉只列出启用类型，顺序按配置排序；来源类型仍是四必填项之一（负责人/截止时间/来源/标题缺失时不可保存，与 r1 AC-6 一致）。
- 选择「需绑定会议」形态的类型：必须选择来源会议与决议项，缺一返回 400 并在对应字段展示错误文案；该决议项全局只能生成一条任务（沿用唯一约束）。
- 选择「自由说明」形态的类型：来源说明必填 1–200 字，缺填 400。
- 未知编码、已停用编码或形态与字段不匹配的请求返回 400，`fieldErrors.sourceType` 给出具体原因；数据库层仍保留 `source_type NOT NULL` 与决议项唯一约束，不得因为可配置化而放宽这两条。
- 会议决议一键转任务固定使用内置的会议型来源，生成的来源快照（会议标题、决议项描述）与 r1 一致。

**AC-5 配置同源一致**
- meta 选项、新建表单、任务池筛选、矩阵筛选、看板筛选、列表/详情标签，全部读同一份来源配置；不得再有硬编码的三类枚举分支（`SourceType.values()` 直接喂下拉的做法必须移除）。
- 筛选项按来源编码精确匹配（大小写归一）；未知编码返回 400 且提示「来源类型不合法」；旧链接里的 `sourceType=MEETING` 等参数继续可用。
- 新增一个来源后，在任务池、矩阵两处都能按它筛选，且筛选结果条数与按该来源建的任务数一致。

### US-3 老用户升级无感（P0）

作为已在用系统的用户，升级后我不需要做任何操作，历史任务的来源显示与筛选都不变。

**AC-3 升级兼容与内置数据**
- 数据库迁移自动写入三条内置来源：`MEETING`=会议决议、`PROJECT`=项目任务、`DAILY`=日常待办，颜色与升级前 `SourceTag` 三色一致，排序 0/1/2，全部启用。
- 升级不改写任何 `tasks` 行的来源字段；升级后历史任务在任务池、详情、矩阵、看板、筛选中的名称与颜色与升级前逐项一致（同一任务升级前后截图/接口对照无差异）。
- 内置会议决议不可删除、不可停用；改其名称后全站（含历史任务标签、筛选、看板）统一显示新名称——这是明确接受的语义（不做逐任务快照）。

### US-4 负责人随时补充进度（P0）

作为负责人，我要在任务里随时写一句「客户已确认口径，等合同盖章」，让派发人和管理层看到最新进展，而不必改变任务状态。

**AC-7 进度追加**
- 任务详情页时间线支持追加进度：输入框在时间线上方，文字必填 1–500 字（去首尾空格后判空），纯文本。
- 提交成功后 1 秒内出现在时间线顶部，展示作者、时间、正文、@ 的人；刷新页面后仍在，顺序稳定（同一秒内按 id 倒序）。
- 进度只能追加，不提供编辑与删除；单任务进度上限 200 条，超限返回 409「该任务进度已达 200 条上限」。
- 任何任务状态（含已验收、已取消）都可补充进度；补充不改变任务状态、不写状态流转事件。
- 时间线合并展示状态流转与进度，两类条目样式可区分（流转条目保留原 `TransitionTimeline` 信息，进度条目显示作者与 @ 人）。

**AC-8 进度写入权限**
- 可补充进度的人 = 能查看该任务的人：负责人、管理员、管理层，以及因被 @ 而获得可见权的成员（AC-11）。
- 其他用户提交进度返回 403；打开任务详情仍返回 404（沿用越界不泄露存在性的既有口径）。
- 补充进度不授予任何状态动作：即使能补进度，验收/打回/改派/改期/取消/催办的权限判定与 r1 完全一致。
- 停用用户其会话已失效，不能提交进度（复用现有登录态校验，不新增例外）。

**AC-12 口径不变（回归）**
- 补进度不修改 `tasks.status / due_date / owner_id / dispatcher_id`，不写 `task_events`。
- 同一 `today` 下，补进度前后任务池条数与排序、矩阵五列数字、看板 6 项 KPI、逾期数完全一致（接口快照对照）。
- 任务池「更新时间」列与排序不受进度影响，仍以任务字段变更为准。

### US-5 成员被 @ 后收到通知并能跟进（P0/P1）

作为被 @ 的同事，我要立刻收到通知，点开就能看到上下文并继续补充进度。

**AC-9 @ 成员选择**
- 输入「@」或点击 @ 按钮弹出成员选择：仅列出启用用户（排除自己），支持按姓名/账号关键字过滤，可多选，单条进度最多 @ 10 人，重复选择自动去重。
- 仅有通过选择器选中的成员才算提及；正文里手打「@张三」而未选中，不产生通知、不获得可见性（避免误报与越权）。
- 提交后正文中的被 @ 人显示为高亮姓名；同一条进度内重复 @ 同一人只算一次。

**AC-10 @ 通知（站内 + 钉钉 + 降级 + 幂等）**
- 每个被 @ 人生成一条通知：类型 `MENTION`，标题「{作者} 在任务《{任务标题}》中@了你」，正文为进度摘要（截断 100 字，超出以「…」结尾）。
- 站内：通知中心列表可见，该用户未读角标 +1；点击通知跳转任务详情并定位到该条进度（锚点 `#progress-{id}`），进入即标记已读。
- 钉钉已配置：复用现有工作通知通道与状态五值（`PENDING/SENT/FAILED/NOT_CONFIGURED/UNBOUND`）及 1/5/15 分钟退避；发送异步，进度提交响应不等待钉钉结果。
- 钉钉未配置或用户未绑定：通知照常入库（状态 `NOT_CONFIGURED` / `UNBOUND`），进度提交照常成功、无 500、无阻塞。
- 幂等：同一进度、同一被 @ 人仅一条通知（去重键含进度 id 与用户 id）；重复点击提交或钉钉重试都不产生第二条站内通知。

**AC-11 被 @ 人获得任务可见性（取代 r1 AC-2 的可见范围）**
- 被 @ 的成员打开该任务详情由 404 变为 200：可见任务全量详情、全部进度与流转记录。
- 被 @ 人可在该任务下继续补充进度（可继续 @ 他人），但所有状态类动作按钮均不出现/不可用：开始、提交验收、验收、打回、取消、恢复、强制完成、改派、改期、催办，接口调用一律 403。
- 口径不变：被 @ 人不计入负责人维度，不改变矩阵行、看板 KPI、日报收件人与统计；「越权 404」规则对未被 @ 且非负责人/管理员/管理层的人仍然有效。

**AC-13 通知中心承载新类型**
- 通知类型新增「@我的」标签，通知中心列表展示该标签，未读角标与「全部已读」统计包含 MENTION。
- 通知只读本人不变：他人通知不可见；@ 通知不因任务后续状态变化而撤回（保留历史）。

## 5. 交互流程摘要

**流程 A · 管理员配置来源**：设置页 →「来源配置」→ 新增（填名称、选形态、选颜色）→ 保存 → 列表出现新行、排序可调 → 派发人下次打开新建抽屉即可选到。

**流程 B · 建任务选来源**：任务池「新建任务」→ 来源下拉（仅启用项）→ 选「需绑定会议」型 → 出现会议/决议项选择；选「自由说明」型 → 出现 1–200 字说明框 → 四字段齐全后保存 → 任务入池，标签用配置的颜色与名称。

**流程 C · 补进度 @ 人**：任务详情 → 时间线顶部输入 → 输入 @ 弹出成员（可搜索、多选）→ 提交 → 条目立刻插入时间线顶部、@ 人高亮 → 被 @ 人收到站内通知（钉钉已配置时同时推送）→ 点通知进入详情定位到该条 → 被 @ 人可补充后续进度。

**流程 D · 停用/删除来源**：设置页列表 → 停用（历史任务照常显示，新建不可选）；删除仅在引用数为 0 时可用，否则给出「只能停用」的提示。

## 7. 依赖与风险

**依赖**
- 依赖 r1 既有能力：`NotificationService.createIfAbsent` 的 `dedup_key` 幂等（`server/src/main/java/com/pmo/supervise/notify/NotificationService.java:53`）、`TaskAccessGuard` 单点权限（`server/src/main/java/com/pmo/supervise/task/TaskAccessGuard.java:14-21`）、`TaskService.permissions` 服务端算权限（`server/src/main/java/com/pmo/supervise/task/TaskService.java:117-170`）、钉钉降级契约。
- 数据库迁移：本需求需要一条新的 Flyway 迁移（V4）建配置表与进度相关表，并替换 `ck_tasks_source`。

**风险**
1. 来源枚举耦合点分散（后端 12 处、前端 8 处），只改表单不改查询会导致「建得出、筛不到」。缓解：AC-5 以「新增来源后两处筛选都可用」为验收动作。
2. `ck_tasks_source` 是库层兜底，改为可配置后形态约束上移应用层，存在「接口放过、库层也放过」的空档。缓解：保留 `source_type NOT NULL` 与决议项唯一约束，形态校验保留服务端单点，并补库层结构性 CHECK（迁移方案由技术阶段裁定）。
3. 被 @ 可见性与 r1「越权 404」冲突，若实现时只在详情放开、列表不放，会出现「通知点得开、任务池搜不到」的割裂。本轮明确：被 @ 人不在任务池列表中额外出现（列表仍按角色过滤），仅保证详情可达与进度可续写；技术阶段需在权限判定处显式表达。
4. 通知放大：一条进度 @ 10 人即 10 条通知，若再叠加钉钉重试可能触发通道限速。沿用现有退避与限速，不做每用户合并（合并会丢「谁被 @」语义）。
5. 真实钉钉送达仍需凭证（r1 遗留的人工补测项），本轮不改变该环境限制。

以下每条都是需要用户拍板的口径，括号内为推荐默认值与影响：

- **@ 是否授予任务可见性**（推荐：是，被 @ 即可打开详情并继续补进度，否则通知点开 404，等于通知无效）。若选择「不授予」，则 @ 只能选已可见成员，普通同事无法被拉进任务，需求价值大幅缩水；若选择「仅通知不给详情」，通知文案需去掉跳转，且会持续产生点开即 404 的困惑。
- **已结束任务是否允许继续补进度**（推荐：允许，作为结项说明/复盘记录，纯文字不改状态）。若不允许，负责人验收后想补一句「归档位置」就没有入口；若允许，需接受时间线在任务结束后仍增长。
- **补进度是否自动把「待办」推进为「进行中」**（推荐：不自动，状态仍由「开始处理」显式驱动，避免用户没点按钮数字却变）。若选择自动，则矩阵/看板的进行中口径会因一条评论而变化，需要同步调整 AC-12 的回归基线。
- **来源类型是否支持「需绑定会议」形态开关**（推荐：支持，作为每个类型的属性，新建默认「自由说明」，仅内置会议决议为「需绑定会议」）。若不支持，所有新类型都只能是自由说明，与「会议决议」形态不对称；若支持，管理员需理解两种形态的差别（页面需一句说明）。
- **被引用的来源能否删除**（推荐：不能，只能停用；未引用可物理删除）。若允许强删，历史任务需改为「未知来源」展示，与反面目标 5 冲突。
- **来源改名是否回溯历史任务显示**（推荐：回溯，全站单一名称，不做逐任务快照）。若要求快照，需要给任务表加来源名称快照列，历史任务将保留旧名，筛选与标签会出现两种叫法。
- **进度是否需要百分比/附件**（推荐：本轮都不做，纯文字 1–500 字）。若需要百分比，需定义进度值与状态的关系（是否自动置为进行中）、矩阵是否展示平均进度；若需要附件，需定义存储位置与访问权限。
- **@ 上限 10 人、单任务进度上限 200 条是否合适**（推荐：保留，作为防刷屏与防滥用的默认值）。若业务上需要一次 @ 整个项目组，需提高上限并评估钉钉调用量。
